# Published provider migration: local verification

The Next.js and Vite starters consume registry-published services 11.0.0, core 4.1.0, contracts 4.8.0 and peer-compatible Bloom 6.4.0. Each starter passes frozen Bun install, its typecheck and production build. Vite development also mounts and runs the OAuth fixture. The record pins registry metadata, exact base, toolchain and evidence hashes.

An isolated Playwright check outside the starter repository serves each actual browser bundle. All API/IdP requests are intercepted, with a synthetic public application classified `third_party`, exact local registered-URI fixture, and RFC OAuth token response without `deviceId` or `deviceSecret`. The fixture refuses shared-device endpoints. It checks no authorization before a click, S256 challenge/verifier equality, same callback URI and client ID at exchange, signed-in display, zero cookies, and wrong-state rejection before exchange. Next and Vite production plus Vite development pass those assertions.

**Expected logout remains RED on the published SDK.** Pressing Sign out leaves the user authenticated and issues no self-revocation request: services `src/ui/context/hooks/useAuthOperations.ts`296–313 requires a device account in `SessionClient` state. The synthetic isolated session has none. The browser runner exits 1 deliberately for this gap; its individual state-mismatch checks pass, and no successful device fixture is invented. Full adoption is unchecked pending an upstream lifecycle correction and verified published release.

The builds use synthetic configuration only: API `http://127.0.0.1:17855`, client `oxy_dk_fixture_not_registered`, callback roots on localhost ports17854 (Next),17853 (Vite preview),17856 (Vite development). The fixture ID is never registered. Production builds remain configured by the required public environment settings documented in each `.env.example`.

Commands: each starter `bun install --frozen-lockfile --minimum-release-age=0`, `bun run typecheck`, and `bun run build` with the above synthetic environment; Next `bun run start -- --hostname localhost --port 17854`; Vite preview `bun run preview -- --host localhost --port 17853 --strictPort`; Vite development `bun run dev -- --host localhost --port 17856 --strictPort`. Browser fixtures were executed with Node 24 and Playwright imported from the existing isolated website review toolchain; no test setup was added to a starter. Exact external runner/log paths and hashes are in the JSON; the upstream lifecycle followup will carry the reusable regression proof.

Build warnings remain: Vite bundle size and unreachable Node crypto import; Next optional native dynamic import. These are not live SSO, API authorization, provider-consent, deployment or Android results. Expo retains its legacy source until the SDK supplies a shared native callback finalizer; no local callback/token plumbing or unsafe DTO cast is introduced.
